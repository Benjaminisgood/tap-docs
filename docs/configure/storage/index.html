文件与存储位置

在工作台打开 文件与 OSS → 管理位置，添加 OSS 连接和 TAP 主机上已挂载的目录。位置保存在当前 TAP 实例中，各聊天复用；当前聊天的工作区仍跟随聊天。全局设置不再提供单独的“存储”页。

“本机”是打开网页的电脑或手机；“服务器”是运行 TAP 的机器。NAS、SMB、NFS 等共享目录只有先挂载到 TAP 主机并允许 TAP 访问，才属于服务器位置。浏览器不会把自己电脑上的共享目录自动暴露给远端 TAP。

添加已挂载目录​

在 管理位置 → 挂载目录与常用位置 中点 发现已挂载目录，选择需要的路径并填写名称；也可点 添加目录，手动填写或浏览已存在的绝对目录。发现操作只读取当前运行环境的挂载信息，不扫描局域网、不连接未挂载的设备，也不要求填写 NAS 密码。

保存前会检查路径。只读位置可作为复制来源，不能作为目标。删除位置只移除登记，不删除目录或其中的文件。设备断开后，重新连接系统挂载，再刷新位置或重新检查目录。

管理服务器目录需要管理员登录及已有的路径访问权限。Docker 部署方显式声明的存储挂载可供管理员在文件工作台使用；其他工作区外目录仍受原有完整访问限制。保存一个位置不会授予普通用户权限，他们仍只能访问自己的目录和授权项目。

原有的独立 局域网传输 工具使用 SSH/SFTP 连接远端主机，与这里已经挂载的文件系统目录是两种入口。

添加连接​

打开 文件与 OSS → 管理位置 → 添加连接，填写：

字段示例或含义
名称实验数据
Bucket你的 OSS Bucket 名称
Endpointhttps://oss-cn-hangzhou.aliyuncs.com，使用阿里云官方 HTTPS 地址
地域cn-hangzhou，与 Bucket 地域一致
目录前缀可选，例如 experiments/，限制此连接可访问的对象范围
AccessKey ID / Secret此连接使用的凭据，替换时同时填写两项
STS Token使用临时凭据时填写
只读访问默认开启；需要上传时为对应连接关闭

保存后使用 检查连接 验证目录访问。保存成功只表示配置已保存，连接检查成功才说明当前凭据能读取指定位置。

凭据存放在当前 TAP 实例配置目录的 auth/oss/ 中，不写入普通配置文件、不回显到页面。编辑已有连接时，凭据留空会保留原值。TAP 不读取 TPX 或 TAK 的凭据文件。

管理员登录可以启用、添加、修改和删除这些连接，包括从别的电脑打开 Docker 发布出来的地址。权限跟这次登录的令牌走。浏览器在不在运行 TAP 的那台电脑上，以及 TAP_ALLOW_REMOTE_STORAGE_CONFIG，都不能授予或取消这项权限。OSS 凭据在这台 TAP 的凭据库里，不需要浏览器和 TAP 在同一台电脑，也不需要为了改连接而做 SSH 隧道。

从门户进入时，账号与空间由门户管理；独立运行仍使用当前实例的 tokenIssueSecret 或兼容 token 登录。TAP 不再提供“用户与密钥”设置页。存储操作继续按当前实例身份与工作区权限检查，详见账号与登录。门户 Agent token 和模型 API Key 不能替代应用登录。

未登录或令牌无效不能改连接。浏览工作区以外的本机目录、完全文件访问，以及系统文件夹选择器，仍然只给运行 TAP 的那台电脑上的管理员浏览器。远程管理员也不能使用它们，因为它们依赖这台电脑的文件系统和系统对话框。

也可在启动 TAP 服务的环境中设置 TAP_OSS_ACCESS_KEY_ID、TAP_OSS_ACCESS_KEY_SECRET，以及可选的 TAP_OSS_SECURITY_TOKEN。使用 Docker 时，环境变量必须传入容器；通常直接在设置页填写更方便。

浏览和传输​

在当前对话的工作台点 + → 文件与 OSS。顶部直接选择 本机、服务器、OSS 或已添加的挂载位置，例如“实验 NAS”“归档 NAS”。挂载位置使用保存的名称，标明只读或不可用；不再通过“当前工作区”下拉框切换。从 Apps 列表打开会新建所属对话；要接着现有项目工作，使用当前工作台的 +。

目录栏显示位置名称与相对目录，点击面包屑返回上级。默认不显示 Docker 内部路径；需要直接定位时可展开 输入路径。目录列表支持分页，文件支持文本和图片预览；超过预览大小的文件需要完整下载后查看。

  • 目录之间复制：选中文件并点 复制到其他位置，或进入源目录后点 复制此目录。在弹窗中选择位置，逐级打开目标文件夹，只需确认副本名称，再点 复制到此处。
  • 下载文件：选择 OSS 文件，点 放入服务器，浏览目标目录并确认文件名称。也可保存到浏览器所在的本机。
  • 创建工作副本：在 OSS 目录点 复制目录到服务器，选择父目录并填写副本文件夹名称。TAP 下载完整文件树，完成后才发布该目录。
  • 上传文件：选中服务器或 NAS 中的文件，点 存到 OSS，浏览 OSS 连接中的目标目录并确认名称。本机文件先用文件选择器选取，再选择 OSS 目标目录，单次上限为 8 MiB。

弹窗的目标浏览与主列表互相独立，取消会保留原目录和文件预览。只读、离线位置不能作为目标；目录不能复制进自身。同名项目不会被覆盖，发生冲突时保留已选目录和名称，修改名称后可以重试。

例如，把 NAS 中的原始数据复制到服务器工作区处理，再将结果复制回 NAS 的新目录或上传到 OSS。工作区与 NAS 之间直接复制，不必经过 OSS。浏览器本机文件仍使用已有的本机 ↔ OSS 流程。

浏览、复制与上传使用同一账号和当前会话的访问范围。受限会话只显示项目内的位置，不能借复制访问外部 NAS 或 OSS；切换会话工作区或权限后，旧页面的传输请求会被拒绝，需要重新打开文件工作台。

这些传输默认不覆盖已有文件。创建工作副本时保留原始文件字节，记录来源路径、大小、ETag 和 SHA-256；来源回执保存在 TAP 实例的 storage/imports/ 中。传输失败不会把不完整目录作为成功的工作副本。

Docker 中的挂载目录​

Docker 只能看到映射进容器的路径。宿主机已经连接 NAS，并不等于 TAP 容器也能看到。先在宿主机挂载共享目录，再配置 Docker；不要把 NAS 密码写入 TAP 配置或 Compose 文件。

部署方同时通过 TAP_STORAGE_MOUNT_PATHS 声明哪些映射目录允许管理员在文件工作台使用。只有环境变量却没有实际绑定目录，不会让主机文件凭空出现在容器中。这项授权限于管理员的存储操作，不改变 Agent、命令执行或科学计算的工作区隔离；在挂载目录中选好数据后，应先复制到工作区再处理。

macOS 启动器​

启动TAP-Docker.command 自动发现当前 Mac 上已挂载且可读取的 SMB、NFS、AFP、WebDAV 和 SSHFS 目录，并逐个以相同绝对路径映射进 TAP。它不会映射整个 /Volumes，不会创建不存在的源目录。宿主机只读挂载在容器中也保持只读。

./启动TAP-Docker.command --check
./启动TAP-Docker.command --no-open

--check 显示将映射的目录并检查编排，不启动或修改容器。添加、断开后重新连接、或改变挂载点后，重新运行启动器更新容器；仅在网页刷新不会增加 Docker 挂载。自动发现的离线目录会跳过并提示，显式指定却不可访问的目录会阻止更新。

需要补充特定目录时，使用 JSON 路径数组：

TAP_STORAGE_MOUNT_PATHS='["/Volumes/Lab NAS", "/Users/ben/shared-data"]' \
  ./启动TAP-Docker.command --no-open

该变量只对这次命令生效，之后更新时应传入同一设置。TAP_STORAGE_DISCOVER_MOUNTS=0 可关闭自动发现，只映射显式指定的目录。辅助脚本只依赖 Python 标准库，需要 Python 3.9+；有多个解释器时可通过 TAP_STORAGE_PYTHON 指定。

Docker Desktop 若拒绝访问共享目录，先在 Docker Desktop 的文件共享设置中允许该具体目录，再重试。启动器不会自动改变 Docker Desktop 的权限。

Linux 与 Windows Docker​

先在 Docker 宿主环境挂载共享目录。以下示例保存为 docker-compose.storage.yml，在原来的 Compose 文件之后追加使用。source 是 Docker 引擎能访问的宿主路径，target 与环境变量里的路径必须一致；网页中使用 target。

services:
  taptaptap:
    environment:
      TAP_STORAGE_MOUNT_PATHS: '["/data/workspace/mounts/lab"]'
    volumes:
      - type: bind
        source: /mnt/lab-share
        target: /data/workspace/mounts/lab
        read_only: false
        bind:
          create_host_path: false
docker compose -f docker-compose.yml -f docker-compose.storage.yml config --quiet
docker compose -f docker-compose.yml -f docker-compose.storage.yml up -d --force-recreate --wait

保留原部署的项目名和所有覆盖文件；已有 -p personal 或其他 -f 参数也要带上。受限部署的目标应位于它实际授权的工作区内。以上命令不删除持久卷。

Windows Docker Desktop 使用 Linux 容器时，优先在它使用的 WSL 环境中挂载 NAS，然后从同一 WSL 环境执行上述命令。若某个本地 Windows 目录已获 Docker Desktop 共享，可将 source 写为 C:/TAP-shares/lab。Windows 登录用户的映射网络盘不保证对 Docker 引擎可见；不能只把 Z: 写进去就认为已经挂载。把宿主路径换成实际可读目录，保持 create_host_path: false，先通过 Compose 检查和容器中的目录读取验证。

用于 TAP 实验处理​

先创建本地工作副本，再在该副本中开始聊天，通过 TAP 原有目录与命令合同处理数据。oss:// 地址是对象存储位置，不能直接作为本地工作区或交给要求本地路径的科学计算命令。

受限项目通过本地副本工作；Agent 直接访问 OSS 需要完全文件访问权限，且仍受连接的前缀和只读设置限制。保密部署与沙箱不会因为添加 OSS 连接而获得额外访问权限。

处理结果由你单独上传，不会自动同步回 OSS。文件传输和完整性校验通过不代表实验结果已经科学审核。

安装​

TAP Docker 镜像包含 OSS 依赖。本机 Python 环境按需安装：

python -m pip install '.[oss]'

在 TAP 仓库目录运行该命令，并使用启动 TAP 的同一个 Python 环境。没有启用 OSS 时，本地文件功能保持可用。
