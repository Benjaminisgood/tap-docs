使用和部署独立分析工具

WYX 转 SQLite、定量分析、动力学分析、质谱校正和配置文件各有独立工具页面。每个工具有自己的页面，可以分别部署并把地址交给使用者。页面不需要聊天、工作台或 DAG，也不显示返回 TAP 的导航。

如果从 TAP 打开，在 Apps → 工具 中选择对应工具，或从已迁移的分析标签打开。工具在新的浏览器标签中运行。已经登录 TAP 时，这次打开会完成短时交接，不需要再填写密钥。在 TAP 的 /tools/ 地址上直接打开时，登录框接受登录 TAP 的同一把用户密钥。页面先向 TAP 确认这把密钥，再换成一次短时交接；工具进程不接收、也不保存这把密钥。没有 TAP 入口、单独发布的地址仍使用该工具自己的密钥。

配置文件工具​

在工具列表打开 配置文件，查看和检查 TOML、标定系数及碎片矩阵，转换为原生 CSV 或 TOML，并导出带校验记录的备份包。它不运行实验分析；修改后的配置仍须在对应分析工具中导入和复核。

把 WYX 转为 SQLite​

  1. 直接打开工具时，先输入这个工具自己的访问密钥，再选择转换范围。从已登录的 TAP 打开时会自动进入。
    • 单个脉冲：选择一个 .wyx，生成一个 SQLite，脉冲表名为 pulses。
    • 一次测试：选择一个测试文件夹，所有 WYX 写入一个 SQLite 的 pulses 表。
    • 多次测试：选择包含多个测试目录的上级文件夹，或继续追加文件夹。生成一个 SQLite，每次测试单独一张表。
  2. 检查预览中的测试路径、文件数量、采样点数量、AMU、温度和记录时间。
  3. 放大器和检测器按每个文件头写入。版本 2 的文件头标明 Hiden，并用增益模式标明 SEM 或 Faraday。版本 1 且量程序号在 7 到 13 的文件按 LabVIEW 的 Hiden 记录处理；量程序号在这之外的按 SR570 处理。文件头没有检测器名称时，这一列留空。
  4. 每个脉冲按自己的 AMU 写入面积。文件头里的阀 A、阀 B 两个槽都会写入脉冲表，原始数组仍留在文件头表中。不同测试的通道可以不同，不需要为整批数据选一个面积序号。
  5. 确认输出文件名，点击 生成 SQLite 文件，完成后点击 下载 SQLite。

转换在浏览器内运行，不上传 WYX，也不修改源文件。工具自己的服务器在转换前创建记录，转换完成后保存状态、输入计数、输出大小和 SHA256。读取、转换和写库分别显示进度；取消 会终止本次转换并提交取消记录。损坏文件和重复脉冲会列在未纳入清单中，部分成功的结果会明确显示这一状态。

浏览器文件夹选择框中的“上传”是授予页面读取所选文件的通用提示，不代表工具会发送文件。大目录建议直接拖入页面，可查看目录扫描进度并取消；使用选择框时，浏览器可能先枚举整个目录，页面要等选择框返回后才能显示进度。预览只读取文件头，转换逐文件写入 SQLite。测试和未纳入文件清单每页显示 50 项，所有文件仍完整处理。SQLite 数据库与最终导出仍占用本机内存；超大数据集可按测试目录分别转换。

工具保留全部采样点，不做抽点、平均、基线重算或滤波。signal_v 使用小端 float64 BLOB，原始文件头以字节保存，二者可以重建原始 WYX。单次测试的附加头表为 wyx_header；合并文件的附加头表为 <测试表名>__wyx_header。_export_info 记录来源路径、转换选择和未纳入清单。

多次测试优先以时间戳目录识别测试，例如 20261012090324/Measurement 属于测试 20261012090324。不同路径中出现相同测试名时，使用完整相对测试路径区分。如果浏览器只提供了完全相同的相对路径，重新选择这些目录共同的上级文件夹。

用 SQLite 和 TOML 做定量分析​

  1. 打开定量分析页面。在 TAP 的工具地址上，输入登录 TAP 的用户密钥。从已登录的 TAP 打开时会自动进入。单独发布、没有 TAP 入口的地址仍使用该工具自己的密钥。
  2. 导入 SQLite 数据与已有 TOML 配置。也可以点击 浏览服务器文件，按目录选择当前账号的 SQLite，无需填写服务器路径。
  3. 进入 基线处理，选择基线记录及范围，核对拟合参数后运行。定量流程不要求 Knudsen 验证。
  4. 进入 定量分析，复核实际输入文件、范围、内标、标定表和碎片矩阵后运行。
  5. 检查基线拟合图和响应、基线贡献、总响应三项结果；最后下载 CSV、PNG、本次 TOML 或带可编辑图表的 LibreOffice ODS。三项结果均为相对内标的无量纲响应，不是转化率或物质的量。

输入支持标准脉冲 SQLite，以及已有的按测试分表的 WYX 宽表 SQLite。选择的是文件中的具体测试，合并文件不会自动把所有测试混在一起计算。

每一步带入已保存的参数，仍需按本次实验核对。可以点击 保存参数；切换步骤时也会保存表单修改。高级 TOML 编辑保留完整配置入口。继续已有分析时会恢复 TOML 中的测量、基线及范围。

只会将数据或实际依赖参数已变化的结果标为历史结果，例如修改标定系数不要求重跑基线。历史 CSV 保留可下载；下游计算只使用仍有效的前序结果。处理范围默认包含全部记录；页面提供完整连续范围供明确选择，不会自动裁切。

主要 CSV 包括 baseline_points.csv、baseline_fit_parameters.csv，以及定量计算生成的面积表，例如 quant_response_areas.csv、quant_baseline_areas.csv 和 quant_total_areas.csv。实际文件列表以本次结果页为准。输出目录同时保留配置快照、输入与配置摘要及 CSV 哈希。

用 SQLite 和 TOML 做动力学分析​

  1. 打开动力学分析页面。在 TAP 的工具地址上，输入登录 TAP 的用户密钥。从已登录的 TAP 打开时会自动进入。单独发布、没有 TAP 入口的地址仍使用该工具自己的密钥。
  2. 在导入页添加 SQLite 与已有 TOML。
  3. 进入 Knudsen 验证，点击 选择数据，在弹窗中选择测量测试与范围。完成选择后，填写内标 AMU，核对反应器与拟合设置并运行。
  4. 进入 基线处理，选择基线测试与范围，核对拟合参数后运行。
  5. 进入 脉冲量，复核测量数据、各管路体积、参考温度和阀到管路的映射后运行。
  6. 在 参数确认 中复核已保存的标定表、碎片矩阵、内标、进料组成、几何以及 Base 手动 / Pro 自动滤波设置，再进入 Y-procedure 运行。独立基线拟合和脉冲量均是前置结果。
  7. 检查各步骤结果，下载 CSV 和本次 TOML。

参数只在对应步骤出现，之前填写的值会带入下一次复核。管路体积、标定、碎片矩阵和组成可直接在表格中修改。与定量工具相同，只有依赖已变化的结果需要重跑，配置版本号变化本身不会让全部结果失效。

主页面只显示已选数据的摘要。点击 更改数据 / 查看范围 可以重新打开弹窗，按测试名称、文件名、表名或 AMU 检索数据。检索和翻页不会清除已有角色或处理范围，点击 完成选择 返回参数页。

遇到不完整 AMU 循环时，在数据弹窗中选中待处理的脉冲实验，打开其处理范围，点击 修剪到完整循环。页面显示原始、保留和排除的记录数。例如 AMU 按 20, 15 交替的 305 条记录，末尾只有 20 时，可以保留前 304 条，共 152 个完整循环。修剪只设置本次分析的记录范围，不改写 SQLite，也不删减保留曲线中的采样点。点击 使用全部记录 可以恢复选择。

如果存在多段完整连续范围，可以明确选择其中一段，工具不会跨过中间缺失的记录拼接循环。也可以手动输入范围，页面记录编号从 1 开始，包含起点和终点；TOML/API 仍使用零起始、结束不包含的范围。基线按每条记录独立拟合，可任意裁剪，不要求完整循环。定量等要求完整循环的步骤会提示调整后再运行；采样时间轴是否兼容，由各分析步骤按实际使用的通道检查。重复 AMU 通道仍需要明确的通道映射，修剪不能替代映射。运行后，选区会保存到本次 TOML 和处理记录中；改变选区后，依赖该数据的旧结果需要重跑。

信号增益与预触发区间来自 SQLite 记录，不另外填写 [signal]。几何配置明确给出区段长度与孔隙率时，计算采用这些区段；否则使用总长、床层长度与孔隙率解析区段。Y-procedure 需要两个扩散区段。

[kinetics_tool.composition] 使用与 calibration.species 完全一致的物种标签，进料摩尔分数之和必须为 1。参考温度使用 K，阀与进料管路映射需要明确填写。number_of_sequences_to_average 是显式的序列平均设置，默认为 1；它不缩减每条曲线的采样点。

除 Knudsen 和基线 CSV 外，主要结果包括 pulse_size.csv、y_procedure.csv、filter_review.csv 和 filter_spectra.csv。Y-procedure 先按每条记录的采集时间扣除独立拟合的漂移基线，再执行后续处理，不额外重复扣除触发前均值。旧版仅扣预触发基线的历史结果会提示重新运行。结果可导出为带来源记录和可编辑图表的 LibreOffice ODS。

这里的动力学分析重构出口流量、反应速率和浓度等时序结果，不自动完成微观动力学机理辨识。任务完成、CSV 生成或哈希一致表示技术执行结果，科学结论仍需结合实验条件与曲线检查确认。

分别构建五个工具前端​

在仓库根目录运行：

npm --prefix webui ci
npm --prefix webui run build:tools

构建输出分别位于：

  • dist-tools/wyx-sqlite/，入口 wyx-sqlite.html。
  • dist-tools/quantitative/，入口 quantitative.html。
  • dist-tools/kinetics/，入口 kinetics.html。
  • dist-tools/configuration/，入口 configuration.html。
  • dist-tools/mass-calibration/，入口 mass-calibration.html。

每个目录包含自己的前端与资源文件，可以单独复制到服务器。资源使用相对路径，不要求其他工具或聊天界面的文件。不要只复制 HTML，assets/ 也需要一起部署。

只构建其中一个工具时，在命令后指定名称：

npm --prefix webui run build:tools -- quantitative

部署 WYX 转 SQLite​

WYX 转换前端连接自己的认证与记录服务。使用独立的端口、数据目录和密钥启动：

taptap-wyx-sqlite-tool serve \
  --host 127.0.0.1 \
  --port 8893 \
  --data-dir "$HOME/.tap-wyx-sqlite-tool" \
  --access-key-file "$HOME/.tap-wyx-sqlite-tool/access-key.txt" \
  --static-dir dist-tools/wyx-sqlite

打开 http://127.0.0.1:8893/wyx-sqlite.html，输入这个工具的密钥。WYX 计算仍在浏览器，服务只负责本工具的身份与记录。页面与 /api/wyx-sqlite-tool 保持同源；远程部署使用 HTTPS。

默认页面需要先成功创建服务器记录，才能开始转换。纯静态服务器只能提供资源，不能提供这套归档流程；不要把纯静态部署当作有服务器记录的服务。

部署定量分析服务​

在安装了本项目 Python 包及科学计算依赖的环境中，从仓库根目录运行：

mkdir -p "$HOME/quantitative-data"
taptap-quantitative-tool serve \
	--host 127.0.0.1 \
	--port 8891 \
	--data-dir "$HOME/.tap-quantitative-tool" \
	--workspace "$HOME/quantitative-data" \
	--access-key-file "$HOME/.tap-quantitative-tool/access-key.txt" \
	--static-dir dist-tools/quantitative

打开 http://127.0.0.1:8891/quantitative.html。首次启动会创建独立的访问密钥文件，终端打印密钥文件路径。在登录表单中输入该文件里的密钥。

--data-dir 保存本工具的项目、上传文件、任务日志和结果。--workspace 指定允许从服务器导入 SQLite 的目录；该目录必须存在。--static-dir 指向本工具的独立前端构建目录。

部署动力学分析服务​

用独立的端口、工作区、数据目录与密钥启动：

mkdir -p "$HOME/kinetics-data"
taptap-kinetics-tool serve \
	--host 127.0.0.1 \
	--port 8892 \
	--data-dir "$HOME/.tap-kinetics-tool" \
	--workspace "$HOME/kinetics-data" \
	--access-key-file "$HOME/.tap-kinetics-tool/access-key.txt" \
	--static-dir dist-tools/kinetics

打开 http://127.0.0.1:8892/kinetics.html，输入动力学工具的密钥。两个分析服务可以分别启动、更新和停止，均不要求 TAP 网关进程运行。

给远程使用者提供服务时，按服务器部署方式设置监听地址，并为每个分析工具分别转发它的页面、资源和 API。定量工具的 API 前缀为 /api/quantitative-tool，动力学工具为 /api/kinetics-tool。页面与自己的 API 保持同源；通过 HTTPS 反向代理分发地址与各自的密钥。

在 confidential Docker 部署中运行独立工具​

confidential Agent 镜像不包含科学计算代码。根目录的 docker-compose.yml 已包含四个独立工具容器，每个工具使用自己的前端、服务、项目数据卷和私有网络。

docker compose build
docker compose up -d --no-build --wait

沿用部署时的项目名、环境文件及宿主机挂载配置。docker-compose.override.example.yml 和 macOS 启动器的 overlay 会把 TAP_WORKSPACE_HOST 同时挂入三个分析工具的 /data/workspace，工具只读源文件，将导入副本和结果写入各自的 /data/tool。未设置宿主机绑定时，它们只读同一 TAP 实例的 taptaptap-workspace 卷。WYX 转 SQLite 在浏览器处理本地文件，不需要服务器来源目录。

工具独立地址项目数据卷来源目录
定量分析/tools/quantitative/quantitative-tool-data当前用户的工作区（只读）
动力学分析/tools/kinetics/kinetics-tool-data当前用户的工作区（只读）
质谱校正/tools/mass-calibration/mass-calibration-tool-data当前用户的工作区（只读）
WYX 转 SQLite/tools/wyx-sqlite/wyx-sqlite-tool-data浏览器选择的本地文件

tool-ingress 使用原来的 Web 端口，工具端口不发布到主机。TAP 登录通过短时交接进入工具；工具不接收 TAP 的登录密钥。交接密钥由初始化容器生成，以只读卷提供给各服务。没有 TAP 入口的单独部署继续使用该工具的访问密钥。

从服务器选择文件​

定量、动力学导入页点击 浏览服务器文件，进入目录后选择 .sqlite、.sqlite3 或 .db，再点击 导入所选文件。文件列表提供目录导航、文件大小、刷新和分页。质谱校正点击 浏览服务器目录，进入包含 data、baseline 等输入目录的上级目录后点击 导入此目录；导入内容保留相对层级，不增加所选目录的名称。

通过 Portal 登录时，工作文件 对应当前账号的 TAP workspace。普通账号看不到其他账号目录。管理员已有的额外存储挂载以独立位置显示，三个工具只读这些目录。独立 TAP 的 macOS 启动器也会将已发现或由 TAP_STORAGE_MOUNT_PATHS 显式指定的 NAS 目录只读挂入三个工具。切换位置无需知道容器路径。

新增宿主机来源目录需要部署者配置 bind mount，并将容器内目录加入 TAP_STORAGE_MOUNT_PATHS JSON 数组。只填写宿主机路径而没有挂载不会使文件出现在容器内。列表为空时，先确认数据放在当前账号的工作区，且运行容器使用更新后的挂载配置；不要挂载整个系统根目录。

仅浏览与导入开放这些来源目录，工具不修改源文件。隐藏目录、符号链接和工具私有状态不在选择范围内；导入时会再次检查权限。

查看每个工具自己的处理记录​

三个工具各自提供 处理记录 入口，记录保存在该工具自己的服务器数据目录，按访问身份与密钥标识关联。页面显示开始时间、步骤或转换范围、状态、耗时以及数据数量；不保存明文访问密钥。服务可以独立部署，不需要 TAP 的统一记录页面。

定量与动力学的记录由服务器任务执行写入，包含输入与配置摘要、输出摘要。计算成功和归档成功分别呈现；归档待完成时页面会提示检查服务器存储，不能把 CSV 生成当成已归档。

WYX 的源文件和结果留在浏览器。服务器时间是服务收到事件的时间，成功、失败、数量与输出摘要均标记为 client_reported，metering_verified=false。它可以用于查询处理历史，不能直接当作已经验证的收费计量。未收到结束事件的记录显示 等待浏览器结果。如果完成事件保存失败，结果仍可下载，页面提供 重试归档；重试使用同一任务的相同完成内容。

给不同使用者分配密钥​

三个工具的 serve 都支持 --user-keys-file。该文件是 用户 ID → 访问密钥 的 JSON 映射，例如：

{
  "researcher-a": "替换为此工具为 researcher-a 分配的独立随机密钥",
  "researcher-b": "替换为此工具为 researcher-b 分配的独立随机密钥"
}

示例文字不是可用密钥。给每个工具创建自己的文件，并分别限制权限：

chmod 600 "$HOME/.tap-wyx-sqlite-tool/user-keys.json"
chmod 600 "$HOME/.tap-quantitative-tool/user-keys.json"
chmod 600 "$HOME/.tap-kinetics-tool/user-keys.json"

在前述启动命令中分别增加对应参数：

  • WYX：--user-keys-file "$HOME/.tap-wyx-sqlite-tool/user-keys.json"
  • 定量：--user-keys-file "$HOME/.tap-quantitative-tool/user-keys.json"
  • 动力学：--user-keys-file "$HOME/.tap-kinetics-tool/user-keys.json"

直接运行 standalone 服务并配置附加 user-keys 时，每个附加用户的服务器来源目录为 --workspace/.tool-users/<用户 ID 的 SHA256 十六进制摘要>，由部署者预置和填充；服务不会自动创建源目录。默认部署者可以浏览 --workspace 和显式存储挂载，其他用户只能浏览自己的来源目录。未预置来源目录时仍可上传本地文件。Portal 按账号分配容器和 workspace，不使用这层附加密钥目录。

映射在服务启动时加载，修改后重启对应服务。三个工具分别维护用户映射和密钥，不共用文件、凭据或记录库。--access-key-file 仍可提供默认部署者的访问密钥；使用者的处理记录按其用户 ID 与密钥标识关联。

增加新的独立工具​

新工具按自己的用途接入，保留以下边界：

  1. 创建自己的 HTML 入口和 webui/src/tools/<工具名>/ 页面目录，不导入另一个工具的页面、状态或会话逻辑。
  2. 如果需要服务器，提供自己的后端模块、CLI serve 入口、API 前缀、数据目录、工作区、端口及凭据。确定性的科学计算可以调用对应 SDK。
  3. 在 CLI 应用目录登记工具及其 ui_url，让工具列表在新标签打开该地址；不登记成工作台前端。
  4. 将工具名称加入独立构建配置与构建脚本，每次构建只包含自身入口及依赖，输出到自己的 dist-tools/<工具名>/。
  5. 分别验证工具页面、输入输出、失败与取消，以及独立部署后的资源和 API 地址。

具体的输入合同和科学步骤由该工具维护。增加工具不会把已有工具合并为共享前后端。
