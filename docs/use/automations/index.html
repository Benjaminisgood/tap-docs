自动任务

自动任务是「到点或被触发时，再做一次你已经说清楚的事」。它不代替你看结果。

先选哪一种​

种类什么时候用
定时每天、每隔一段时间，或某个时刻做一次
本地触发你或另一条命令用一个名字来叫醒这段对话
心跳程序按系统里的间隔自己看一眼有没有要处理的事

做实验分析时，优先用普通话题。定时任务适合「到点提醒我去看某个已经写好的目录」这一类事。

创建之前​

  • 这段对话用的工作区是对的。
  • 模型预设可用。taptaptap status 里 Agent 是就绪的。
  • 时区在 Settings → System（设置 → 系统） 里，和你期望的钟点一致。
  • 任务要写的输出目录是新的，不会盖住原始 WYX。

定时​

浏览器侧栏打开 Automations（自动任务），按页面选择时间。保存后，话题右上角能看到下一次运行，或显示已暂停。

对话里也可以用 /goal 把一件持续的事说清楚。那是这一轮的目标，不是日历上的定时。

本地触发​

/trigger 早班查看

回复里会给出这个触发的编号，以及一条可以直接复制的命令，形如 taptaptap trigger 编号 "message"。把 message 换成你要送进这段对话的话。编号以回复里打印的为准，不要自己编。触发不会跳过你对路径和结果的核对。

心跳​

系统设置里有定期检查的间隔。它用来看有没有到期的任务。间隔改短，检查更勤，也更常去问模型。不确定时保持原来的间隔。

查看和停下​

  • 侧栏 Automations 有全部任务和日历。
  • 某一个话题右上角只列和它有关的任务。
  • 页面上可以暂停。暂停之后，下一次不会跑，直到你再打开。
  • /stop 停的是正在进行的一轮，不是整份日历。

结果送到哪里​

定时跑完的回复出现在那个话题里。浏览器或终端当时开着，你会看到；没开着，下次打开同一话题还能看到，只要这段对话是普通话题而不是临时聊天。

失败时，话题里会留下失败说明。先看是模型、路径，还是工作区不对，再改一处重试。

相关​

  • 记忆 是它记下的习惯，不是日程。
  • 一直开着 让关掉窗口之后定时仍能跑。窗口全关且没有后台时，到点的任务不会执行。
