和 Agent 协作

你和 Agent 可以编辑同一份工作台状态：填表、修改技能草稿、准备自动化，或设计定量分析、动力学分析和 DAG 工作流。参数、审批、运行结果保存在服务端，聊天里的描述用于解释它们。

从所属对话开始​

先确认输入框上方的项目目录和访问模式，再打开应用。工作台内打开应用沿用当前对话；从 Apps 应用列表打开会创建所属对话。Skills 列表在当前页面打开详情，不创建聊天或工作台标签；详情编辑后要手动保存。后来要继续修改工作台资源，就回到它所属的对话。

当前没有工作台标签时，Agent 使用通用模式。打开任意逻辑标签后，同一个 Agent 自动获得工作台协作上下文；技能、表单、文件、自动化和科学流程都适用。无需选择“DAG 专用助手”，也不会因为打开应用就启动第二个 Agent。

点击某个标签只提示当前关注对象。Agent 仍保留普通能力；需要改变另一份资源时，应明确说出目标。普通 HTML 页面只有在声明了结构化协作能力后，Agent 才能读取或修改相应字段。

一起改同一份参数​

例如可以发送：

查看当前对话的分析流程，先列出缺少的输入和输出路径。
把我刚改的参数保留下来，补齐其他能从配置中确认的字段，等待我检查。

人和 Agent 的修改都基于当前版本。你修改表单、图或参数后，运行时会把变化交给 Agent；Agent 会读取最新状态，再继续协作。多个窗口同时改动导致版本冲突时，重新加载后合并自己的修改，避免用旧表单覆盖新值。

科学命令先读取当前 catalog，再使用明确的配置、输入和输出。保留原始数据和全部数据点；缺少实验条件时先补齐，不把猜测变成参数。

等待与执行是不同状态​

默认科学命令操作策略是人工批准。审批对应当前参数版本；修改参数后，旧批准失效。Agent 可以准备、读取和修改操作，但不能通过工具伪造人工批准。管理员选择自动策略时，允许执行的范围以当前策略为准。

状态或提示你需要做什么
等待输入 / awaiting_input在原操作里补齐必填参数
等待批准 / awaiting_approval检查命令、配置、输入、输出和参数版本，再批准
依赖未完成查看上游节点，不要重复创建下游任务
运行中查看原运行日志；要停止时使用取消操作
已完成或失败检查实际产物、日志和错误，决定接受或修订

DAG 创建运行时固定一份图版本。之后编辑图定义不会修改已有运行快照；要执行修改后的流程，应核对新版本再创建运行。定量和动力学固定模板在同一对话范围中重复打开会复用已有流程。

“等待输入”或“等待批准”会保存下来，不需要让 Agent 一直轮询，也不需要再建一个同名任务。完成的软件运行只证明命令执行结束；实验基线、校准、定量与动力学结论仍需 由你验收。

刷新、关闭和恢复​

工作台标签按对话、规范化项目路径和准确的访问模式保存。刷新或浏览器断开不会关闭逻辑标签；切换项目或访问模式后，原状态仍属于原范围。

显式关闭最后一个标签，Agent 回到通用模式。关闭视图不会取消已授权任务、删除草稿或撤销运行；需要停止时进入原运行记录并取消。服务重新启动后，未确认的原生事件可以恢复，Agent 重新读取保存的状态。恢复记录不等于保证任意外部进程都能继续执行。

浏览器动作还有单独的状态：

状态含义
awaiting_client请求已保存，等待所属应用在浏览器里打开并领取；尚未完成
succeeded / failed应用已回写动作结果，继续核对领域文件或状态
stale草稿或能力已经改变，旧请求不能照原版本执行
indeterminate执行中断，无法确认结果；先核对目标状态，再决定是否重试

例如，Agent 请求技能编辑器保存草稿时，该适配组件需要打开。普通浏览器动作不会由通用后端凭空执行；CLI 命令由服务端执行器管理，不依赖浏览器标签保持打开。服务恢复时不会自动重复执行结果不明的浏览器动作。

多个对话放在同一组​

对话加入同一个组后，工作台可以汇集成员标签并标明所属对话；点另一个成员的标签会选中它的聊天面板。标签的状态和操作归属不迁移。

Agent 每次处理消息时，可以获得同组、同项目、同访问模式成员的只读工作摘要，例如组件版本、动作状态、流程节点和运行状态。它不会因此拿到其他项目、不同权限范围、临时或已删除对话的内容，也不会获得其他对话的完整草稿正文。

分组不会自动授予跨对话修改、执行或发消息的权限，也不会让 Agent 互相不断触发。需要改成员流程时，切换到资源所属对话继续操作。

可以这样请求​

继续这个对话已有的 DAG，读取当前版本和已有运行。
我只改了节点参数，请保留其他编辑；先验证，不创建重复流程。
解释现在等待我输入或批准的项目，并打开对应视图。

遇到冲突、范围不匹配或恢复提示时，见 遇到问题。
