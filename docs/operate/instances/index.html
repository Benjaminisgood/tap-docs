多份实例

每个人单独的配置、工作区和网页。不要两个人轮流改同一个 config.json。

同一台电脑上开两份​

每份用自己的配置文件和工作区：

taptaptap webui --config /某人的/config.json --workspace /某人的/实验文件夹

两份如果同时开网页，端口不能都是 8888。第二份需要在那份配置里使用另一个本机端口，再用对应地址打开。

终端同样加上 --config 和 --workspace，才会连到同一份。

用 Docker 每人一份​

在项目文件夹里，每人一个项目名：

docker compose -p alice pull && docker compose -p alice up -d
TAP_WEB_PORT=8889 docker compose -p bob pull && TAP_WEB_PORT=8889 docker compose -p bob up -d

镜像标签用 TAP_IMAGE_TAG，不设置时是 latest。本机要改代码时，把上面的启动换成 docker compose -p alice up --build -d。更新已发布的镜像时重复 pull 和 up -d。不要用 docker compose down -v。

浏览器分别打开 http://127.0.0.1:8888 和 http://127.0.0.1:8889。端口默认只给本机。

每人有自己的密码、工作区和对话。帮别人部署时，读取这一份的网页密码：

docker compose -p alice exec taptaptap cat /data/home/.taptaptap/webui-password

把密码交给使用的那个人。不要把两个人的实验目录拷进同一份工作区。

自己在本机完整使用、需要挂上已有实验目录时，用全量源码那份编排，并把目录指到你的实验文件夹。Windows 路径写成 C:/Users/... 这种形式。具体编排文件名是 docker-compose.relaxed.yml（包装名历史遗留，不是另一种产品）：

export TAP_WORKSPACE_HOST="$PWD/my-experiment"
export TAP_MIRROR_HOST="$PWD/my-experiment"
export TAP_MIRROR_PATH=/data/experiment
docker compose -f docker-compose.relaxed.yml -p personal pull
docker compose -f docker-compose.relaxed.yml -p personal up -d

还没有对应的 GHCR 标签时，在 up 上加 --build，从当前目录构建。

给别人用的默认编排不包含仪器直连页面。仪器开关在那种部署里保持关闭。真机操作放在实验室那台允许打开仪器页的环境里。

怎样算分清了​

  • 两边的 taptaptap status 或关于页显示的配置路径不同。
  • 工作区路径不同。
  • 网页地址或密码不同。
  • 在一边放进的 WYX，另一边的话题看不到，除非你故意把文件放进那个工作区。
