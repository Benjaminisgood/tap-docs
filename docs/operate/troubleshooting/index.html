遇到问题

源码安装后找不到已存在的模块​

若从仓库内能启动，但在实验目录执行 taptap-syncthing 等命令提示 No module named taptaptap.apps...，先确认使用的是同一个虚拟环境。可选插件的可编辑安装有时会先占用包命名空间；在 TAP 仓库根目录重新注册核心包路径：

python -m pip install --no-deps -e . --config-settings editable_mode=compat

该命令保留已安装插件和配置，只修复当前 Python 环境的源码路径。不要通过复制实验目录、配置或其他项目的包来绕过问题。

一次只改一件事，改完用「你好」再试。

taptaptap --version
taptaptap status
taptaptap agent -m "你好"

status 不呼叫模型。第三句会真正去问一次。

先看 status​

  • Config 旁边没有勾：还没有配置文件。运行 taptaptap onboard。
  • Workspace 旁边没有勾：工作区文件夹不存在。onboard 会创建默认的那一个，或你把 --workspace 指到已有文件夹。
  • Agent 一行说配置还没就绪：到 Settings → Models 把提供商和主模型保存完整。
  • Model 不是你要的那个：/model 预设名字，或在模型页换预设。

安装​

现象先看这里
找不到 taptaptap这个终端先激活 .venv
Python 版本太低安装 3.12 或更新版本，重开终端
全屏终端起不来安装 Bun 1.4.0 后再运行 taptaptap，或先用 taptaptap --classic
网页提示构建缺失或过期源码检出需要 Bun 或 npm；按 webui 的构建提示更新，再重启已有网关
裸命令出现 Desktop 选择要测试当前源码就选择当前 Python 环境；taptaptap agent 或 taptaptap webui --no-open 会使用当前环境
终端说需要交互式终端taptaptap agent -m "你好"，或 taptaptap --classic

配置​

配置仍是有效 JSON、只是缺少新字段时，可以保留已有值并补齐：

taptaptap onboard --refresh

--refresh 仍要先读取原文件，不能修复 JSON 语法错误。若提示具体行列或字段错误，先备份，再修正对应内容。确需重建时，先把原配置移动到备份路径，再运行 taptaptap onboard 生成新配置，并在设置页重新填入所需值。自定义实例始终带原来的 --config 路径。

模型和密钥​

现象先看这里
输入框写 Model not configured（模型未配置）点 Configure model，新建一个预设
401 或密钥无效密钥属于当前选中的那一家，前后没有空格
找不到模型预设里的名字改成这家现在提供的名字
这一次换成了备用模型提示里写出实际名字。主模型恢复后，下一轮会再试主模型
本机 Ollama 没有回复先确认 Ollama 自己已经在跑，模型名字是已经拉取的那个

后台​

现象先看这里
网页能开，关掉终端就断按需网关随最后一个终端客户端退出。要留下它，用 taptaptap gateway --background；只关浏览器页面不会停止服务
定时任务到点没跑电脑睡着了，或最后一个窗口关掉时没有后台
/restart 之后短暂断开等它重新打开同一地址
taptaptap gateway status
taptaptap gateway logs

网页​

现象先看这里
打不开taptaptap webui 那个终端还在，地址是 http://127.0.0.1:8888
要密码用安装或部署时的密码。本机自己打开通常直接进入
设置保存了却没变化是否提示等待重启
附件发不出去看输入框写的原因：空文件、类型、大小或数量
网页能聊，终端不是同一段/sessions，或退出时打印的 --session 命令
拉取代码后页面还是旧的确认启动器使用的检出和实例，构建前端并重启网关；Docker 要重新构建或拉镜像并重建容器

浏览器默认端口 8888、网关健康端口 18888、serve API 默认端口 8900 各有用途。端口被占用时先核对已有实例；自定义配置的 gateway status/logs 也要带同一份配置与工作区参数。

工作台与协作​

现象先看这里
Agent 等待输入或审批打开原操作，补齐输入或检查当前版本后批准；等待状态会保存，无需另建一个任务
参数保存提示版本冲突 / 409重新读取当前版本，保留其他窗口或人的修改，再提交自己的修改
切项目后找不到草稿草稿属于原对话、项目和访问模式；回到原范围查看
关闭标签后任务还在跑关闭标签只关闭视图；在原运行记录里明确取消任务
动作停在 awaiting_client打开该动作所属对话的应用组件，浏览器适配器才能领取执行
动作显示 indeterminate浏览器或服务中断后无法确认执行结果。先核对目标文件或应用实际状态，再决定重试
同组对话没有自动互相改流程同组信息是同项目、同权限的只读摘要；修改仍要进入资源所属对话

完整操作约定见 和 Agent 协作。

聊天平台​

网页正常、某个聊天软件没有回复时，看 Settings → Channels 里这项是不是已连接，再运行 taptaptap channels status。需要配对时用 /pairing。

文件和仪器​

现象先看这里
它说看不到文件文件在不在当前工作区。输入框上方的项目是不是那个文件夹
它改到了项目以外输入框上方是不是 Full Access。分析数据用默认权限
仪器页面不在侧栏只有实验室那台 Windows 电脑能装仪器控制插件，原生运行或用 启动TAP-Docker.bat 跑 Docker 都行。到 Settings → Apps（应用） 安装并启用 Instrument Control，再重启。其他电脑或没有 Windows 桥接的 Docker 不能安装；没有 Windows 桥接时不能安装该插件（与是否源码隔离无关）。实验室电脑上按钮也是灰的、写着桥接没有响应时，重新运行 启动TAP-Docker.bat，看它打印的桥接日志
仪器没有反应关掉另一个控制台 http://127.0.0.1:8877/。同一台仪器一次只开一处
