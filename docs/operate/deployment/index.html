一直开着

先在 快速开始 里确认「你好」有回复，再让它长期跑。

选一种​

方式适合
终端里开着 taptaptap webui 或 taptaptap人在这台电脑前
taptaptap gateway --background关掉窗口后，这台电脑仍开着，定时任务还要跑
taptaptap gateway install-service登录这台 macOS 或 Linux 后自动起来
Docker一台专门开着的电脑，每人一个地址

随开随关​

直接运行 taptaptap webui 或 taptaptap。在当前 Python 环境启动时，第一个客户端拉起本机共享网关，后开的客户端接上。按需启动的网关在最后一个终端客户端退出后停止；只关浏览器页面不会停止网关。

已经显式放到后台、装成服务、由 Docker 管理或连接到 Desktop 的实例按各自生命周期运行，不能用关闭浏览器来停止。裸命令发现 Desktop 时会让你选择连接目标，检查时先确认自己连到的是哪一份。

终端里的 /detach 会先把服务留在后台，再关画面，并打印停止命令。

后台​

taptaptap gateway --background
taptaptap gateway status
taptaptap gateway logs
taptaptap gateway restart
taptaptap gateway stop

/restart 会重新启动整个程序，页面会短暂断开再连上。

使用自定义配置或工作区启动时，以上管理命令也带同一份 --config 和 --workspace。网页默认端口是 8888，网关健康端口是 18888；二者不同。检查健康不代表模型服务或科学计算已经通过验收。

登录后自动启动​

macOS 使用 LaunchAgent，Linux 使用 systemd 用户服务：

taptaptap gateway install-service --dry-run
taptaptap gateway install-service

先看 --dry-run 打印的内容，再真正安装。卸掉：

taptaptap gateway uninstall-service

Windows 上用后台命令或 Docker，这条安装服务的命令面向 macOS 和 Linux。

Docker​

一台常开的电脑上，按 多份实例 为每个人起一份。网页地址只发布在本机时，外面的网络到不了。要给别人从别的机器打开，由部署的人决定地址和密码，并把密码单独交给使用的人。

给别人用时，优先拉取已经发布的镜像，再启动：

docker compose pull && docker compose up -d

这里是已发布镜像的更新方式；最新 Release 与 cursor 分支最新提交可能不同。默认 docker-compose.yml 是源码隔离部署（Agent + 独立 tap-service），产品体验与本地全量镜像相同。容器不会仅因 git pull 就换成新代码。

停止时用与启动时相同的 Compose 文件和项目名执行 down，不要加 -v。加了 -v 会删掉这一份的持久卷，包括密码、对话或卷内工作区。

macOS 的本地开发线​

仓库提供的 macOS 启动器从当前 cursor 检出构建，更新 personal Compose 项目，等待容器健康：

./启动TAP-Docker.command --check
./启动TAP-Docker.command --no-open

--check 只检查目录与 Compose 配置，--no-open 构建并更新但不自动打开浏览器。启动器使用 docker-compose.yml，并以 docker-compose.override.macos.example.yml 生成临时宿主机挂载覆盖；它不使用上面的发布镜像拉取流程。默认挂载 ~/Desktop、整个 ~/keyoti，并以 ~/keyoti 为工作区；这些目录必须已存在。需要不同目录时，先按启动器支持的 TAP_DESKTOP_HOST、TAP_KEYOTI_HOST、TAP_WORKSPACE_HOST 设置。

已挂载的 NAS 目录会逐个映射进容器，启动器会先检查可读性，不会把整个 /Volumes 挂进去。也可用 TAP_STORAGE_MOUNT_PATHS 指定 JSON 路径数组。连接或重新连接共享目录后，需要再次运行启动器更新容器，随后在 文件与 OSS → 管理位置 中添加。详见文件与存储位置。

网页默认是 http://127.0.0.1:8888。启动器会显示本机网页密码，输出只留在本机。Windows 的实验室部署使用 启动TAP-Docker.bat，仪器仍由 Windows 本机插件桥接控制。

Python 源码安装​

在 cursor 分支确认并保存本地改动后：

git pull --ff-only origin cursor
python -m pip install -e .
taptaptap onboard --refresh
taptaptap gateway restart
taptaptap webui

这些命令使用当前激活的环境和默认配置；自定义实例要带回原来的配置和工作区参数。webui 会检查前端是否需要构建。没有正在运行的网关时，直接 taptaptap webui 启动即可。重启前先查看运行中任务并安排停止时间，持久化状态不保证任意外部进程都能无缝续跑。

连接 GitHub​

Docker 和 pip 安装上，「检查更新」读取 Benjaminisgood/TAP 的最新 Release。仓库若是私有的，未登录的请求会得到 404。页面仍说明仓库可能是私有的、或还没有 Release，并提示先登录。登录只为这一次检查提供令牌，不用于上传技能或其它 git 操作。

在 Settings → About（关于） 点 Connect GitHub（连接 GitHub）。页面显示一次性代码、复制按钮和倒计时，并打开 https://github.com/login/device 。这是 OAuth 设备码流程，不需要浏览器回调，所以 Docker 和从源码安装都可以用。也可以粘贴一个细粒度的 personal access token。程序用 GET /user 确认它有效。

默认 OAuth App 的 client id 是公开的 Ov23liVnueZVvvpRgZ2y。要用另一个应用，设置环境变量 TAP_GITHUB_CLIENT_ID。这里不保存 client secret。

设备码登录请求的范围是 repo 和 read:packages。repo 是 OAuth App 上能读取私有仓库 Release 的最小范围，GitHub 没有更窄的只读私有仓库范围。read:packages 只读软件包，不含写入或删除。检查更新实际只把令牌发给 GET /repos/Benjaminisgood/TAP/releases/latest。细粒度 PAT 可以更窄，只给 Benjaminisgood/TAP 的内容读取权限即可。

这个 OAuth App 打开了 Expire user access tokens。GitHub 文档写明：设备码流程发出的令牌，刷新时不必带 client secret（grant_type=refresh_token，只传 client_id 和 refresh_token）。访问令牌约 8 小时过期，刷新令牌约 6 个月不用则过期。刷新成功后，旧的刷新令牌作废。刷新被拒绝时，关于页要求重新登录。

令牌只写在 taptaptap 主目录的 github-oauth.json（本机是 ~/.taptaptap/，Docker 里是数据卷上的 /data/home/.taptaptap/），文件权限 0600。它不会回到网页，也不会写进日志或 git。退出登录只删除本机这份。没有 client secret，就不能代为在 GitHub 上撤销。OAuth 授权到 GitHub 的 Settings → Applications 里撤销，PAT 在 Developer settings 里删除。

源码隔离部署（Compose 默认：TAP_SERVICE_URL 指向私有 tap-service，Agent 镜像不含 tap/taptap）不提供会写入私有仓库令牌的 GitHub 登录。检查更新仍是未登录的请求，404 保持原来的说明，不提示去登录。产品体验与本地全量镜像相同；不再区分 confidential / relaxed 两种产品模式。

工作台应用插件在所有包装方式下都可安装、启用与使用。源码隔离包装（TAP_SERVICE_URL）仍强制工作区隔离、禁止远程装包进 WebUI、并保持源码不进 Agent 镜像；不再区分 confidential / relaxed 产品模式。

从这份源码安装、并且仓库是 git 检出时，关于页可以在确认后更新并重启。采集还在进行、或这次更新会改到实验数据文件时，它会拒绝。pip 安装不会在页面里自己升级。

开着之后仍要核对​

后台跑完的分析，结果在工作区的文件里。话题里的一句「完成」只说明这一步结束。采用哪一份，仍按 由你验收。
