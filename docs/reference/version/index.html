版本与更新

本手册跟随 TAP 的 cursor 开发线，不是 nanobot 的通用手册，也不是已经发布的稳定版快照。main 保留稳定线，是否发布下一版由项目维护者决定。

最近核对​

2026-11-01，以 TAP 7071640a 为本轮源码核对基线。 本轮补齐并纠正了：

  • 账号入口迁至门户，移除已不存在的本地用户管理操作说明。
  • 独立配置文件、质谱校正、服务器文件选择、定量范围恢复及 ODS 输出。
  • DAG 具名数据端口与文件数量校验，删除旧的“不支持文件映射”说明。
  • Program 文件保存、闭阀基线保存、手动脉冲与仪器配置入口。
  • 文件与 OSS 的位置管理、目标目录浏览和明确点击分享。

近期功能分布在下列页面：

  • 工作台与分析流程：多标签、参数复核、命令操作、定量/动力学固定流程、自由 DAG、节点批准和运行快照。
  • 应用与技能：Apps 打开所属聊天与工作台，Skills 在列表内查看、开关和编辑详情。
  • 协作与恢复：对话范围、共编版本、冲突、跨话题协作和恢复边界。
  • 命令行、程序接口、部署 和 故障排查。
  • 仪器、OSS 与 Papis 的当前入口。

2026-10-25 的历史同步核对 HKUDS nanobot 至 44a7ef53，适配与 TAP 合同兼容的修复：工具参数、MCP 分页、模型兼容、文档读取、API 会话隔离、定时任务恢复和空闲压缩。外观页也已独立于网关设置加载：即使服务端设置暂不可用，本地主题、语言和显示偏好仍可调整。详细采用/延期列表在仓库 docs/agent-upgrade-2026-10-25.md；这不代表已迁入上游全部功能，三态主题与自定义字号尚未迁入 TAP。

运行成功、文档构建成功和图表生成成功各自只证明对应的技术行为；实验条件、基线、拟合与科学结论仍需要人工验收。

确认安装版本​

taptaptap --version
git branch --show-current
git rev-parse --short HEAD

后两条只用于源码仓库。包版本可能在多个开发提交之间保持不变，所以反馈问题时同时记录提交、部署方式、操作系统和出问题的文档页面。Docker 运行的镜像也可能早于磁盘上的源码；拉取代码后需用原来的部署方式更新容器，不能仅凭 Git 提交判断运行版本。

与 nanobot.wiki 的关系​

nanobot.wiki 提供稳定版和 Nightly 入口，并按入门、使用、配置、运行、接入、指南和查阅组织文档。TAP 参考这种组织方式，但命令、渠道、端口、实验流程与应用以 TAP 实现为准。上游新增能力不会自动进入 TAP。

本仓库目前只有一套随 cursor 更新的中文手册，没有复制 nanobot 的多版本、多语言发布体系。文档站点配置中的域名也不证明站点已经上线；本地构建、Git 推送和公网部署是分别验证的步骤。

后续维护​

每次改动用户可见行为，在同一提交中更新对应手册，并更新本页的核对范围。页尾显示文件的 Git 修改时间，提供编辑源文件链接；这表示该页何时被改动，不代表其所有内容都自动重新验证。

仓库 CI 对文档运行依赖锁定安装、TypeScript 检查和 Docusaurus 严格构建，检查侧栏、页面链接与锚点。CI 不能自动判断文字是否符合科学事实，维护者仍需按源码和实际界面审阅。维护命令与说明见仓库 docs/README.md。

四项目文档统一与后续应用对齐范围见 架构基准。

文档站发布​

在线手册位于 tap-docs。2026-11-01 首次通过本地严格构建并发布静态产物，应用源码仓库保持私有。站点根目录 source-revision.txt 记录发布的源码提交。私有仓库 Actions 当前在创建 job 前返回 startup_failure；自动发布配置已保存，备用发布命令见仓库 docs/README.md。
